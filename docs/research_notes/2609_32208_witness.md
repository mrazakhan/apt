# WITNESS — Findings Relevant to APT

Paper: **WITNESS: Discovery and Deciphering of Epiphany in Interactive Puzzle Environments**

arXiv: https://arxiv.org/abs/2609.32208

Reviewed: 2026-10-11

## Why this matters

APT's goal is to understand why a post-training experiment failed to improve held-out accuracy and determine what experiment or intervention should happen next.

WITNESS is useful because it highlights that poor task performance can arise from different causal stages, and that controlled interventions can help separate them.

## 1. Separate discovery from execution

WITNESS uses interventions that help expose whether a model failed to discover the governing rule or still failed after the relevant rule was available.

### APT implication

APT should not treat low held-out accuracy as one undifferentiated failure. Useful stages include capability acquisition/discovery, recognition in the current task, execution, and generalization.

## 2. Controlled interventions are stronger than passive metric inspection

A key carry-forward is: **a good diagnosis proposes an intervention whose predicted outcome differs under competing hypotheses.**

Example: if held-out accuracy is flat, GRPO reward is flat, and most groups are all-zero, plausible causes include tasks being too hard, a bad verifier, a weak starting checkpoint, or an optimization failure.

Useful probes include easier tasks from the same capability family, a trusted/oracle verifier, a stronger starting checkpoint, and fixed-batch optimization replay.

## 3. Environment/interface choices can affect apparent capability

### APT implication

Environment and harness configuration should be first-class experiment metadata. Observation format, tool availability, tool schemas, max steps, system prompt, environment version, task interface, and reset behavior can all confound run comparisons.

## 4. Generalization should be evaluated in multiple regimes

APT should eventually distinguish new instances from known task families, new compositions of known capabilities, held-out capability variants, and entirely new capability families/domains.

## 5. Starting-model readiness matters

WITNESS provides evidence that the same broad training setup need not produce the same improvement across starting models.

### APT implication

Failure to improve under GRPO should not automatically be classified as a GRPO optimization failure. The starting checkpoint may be outside a useful learning regime. This motivates an explicit SFT→GRPO readiness diagnostic family.

## 6. More sophisticated credit assignment is not automatically better

An important negative result is that a more elaborate within-episode credit mechanism did not automatically beat a simpler episode-level scheme.

### APT implication

APT must distinguish temporal association from causal responsibility. Strategy X appearing before reward improves does not prove X caused the improvement; KL rising before accuracy falls does not prove KL caused the regression.

APT should eventually represent causal evidence status explicitly, for example: correlational, supported by intervention, contradicted, or unknown.

## 7. Accuracy remains the outcome

APT should preserve the hierarchy: trusted held-out task success/accuracy → capability-slice accuracy → training-task success → verifier reward → optimizer statistics.

Lower levels help explain higher levels; they should not replace the final objective.

# Carry Forward

- **Diagnostic probes:** controlled experiments that isolate a causal bottleneck.
- **Acquisition vs execution:** do not collapse failure to learn, recognize, and execute into one label.
- **Environment metadata:** record enough harness/environment configuration for trustworthy comparisons.
- **Generalization slices:** evaluate whether improvement survives different distribution shifts.
- **SFT→GRPO readiness:** treat starting-checkpoint capability as a plausible explanation for absent GRPO improvement.
- **Causal evidence status:** separate observations and correlations from intervention evidence.
